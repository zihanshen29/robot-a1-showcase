Unitree A1 面试问题速查

按 2026-07 核实口径整理，适合面试前快速背诵。

项目介绍

Q1：这个项目到底做了什么？

我在 Isaac Lab 中搭建 Unitree A1 仿真控制链路，把站立控制、gated handoff、PPO 步态策略、MPC 求解、accept/reject 门控和日志诊断接起来。600 步 corrected replay 中，PPO 达到 +0.9338 m，接近 hardcoded baseline +0.9339 m；1200 步压力测试中定位到约 872 步共同失败窗口。

Q2：PPO 和 MPC 怎么分工？

PPO 负责高层步态动作，输出 4 个接触通道和 1 个时序通道；MPC 根据当前状态和接触序列求解控制量，并返回 cost、feasible、support force 等诊断信号。这样比直接让 RL 输出全部力矩更容易调试。

Q3：为什么要用 diagonal trot prior？

对角小跑先验降低探索空间，让策略主要学习时序残差。hardcoded baseline 也是 sanity check：如果 baseline 都走不好，就应先排查 MPC、handoff、接触序列或回放语义，而不是怪 PPO。

Q4：16 次训练排错怎么讲？

我不是盲目调参，而是每次修一个可命名问题，包括 warmup residual leak、train/play 不一致、接受门控、接触锁定、时序收窄和课程学习。关键发现是 mpc_rate_div 从 6 改到 1，每个控制步都重解 MPC 后，600 步结果才达到 +0.9338 m。

Q5：corrected replay 的价值是什么？

训练表现好不等于回放可信。如果 train/play 环境语义不一致，checkpoint 排序会错。corrected replay 的价值是先把评估路径校准，再谈哪个模型更好。

指标解释

Q6：PPO +0.9338 m 和 baseline +0.9339 m 接近，说明什么？

说明 600 步短时域中，PPO 没有破坏强 diagonal-trot prior，并且 RL+MPC 链路跑通了。不能包装成 PPO 大幅超过 baseline，真正价值在系统搭建、评估校准和失败定位。

Q7：MPC defaults +0.7915 m 怎么解释？

它是参数对照，说明默认求解调度、接管条件、相位或控制参数没有和当前任务完全匹配。通过对比 PPO、hardcoded baseline 和 defaults，可以把问题定位到系统配置层。

Q8：约 872 步失败窗口说明什么？

1200 步压力测试里，策略和 baseline 都在约 872 步失败，说明不是单纯 PPO 问题，而是共享控制栈问题。后续应查 yaw 漂移、CoM 投影漂移、姿态恢复和 MPC 成本链条。

Q9：yaw-anchor 实验为什么仍判失败？

它存活到 1199 步，但 accept 只有 164/1199。控制长期处于降级或拒绝状态，所以“活得久”不等于“活得好”。这是边界意识，而不是为了好看只报存活步数。

压力追问

Q10：公开仓库是不是只有 demo？

公开仓库确实是脱敏 showcase，使用 synthetic demo 数据，不包含非公开代码、真实日志或 checkpoint。它展示的是数据契约、解析、指标、图表和测试流程；真实毕设指标在 README 中以文字引用，并与公开图表分开。

Q11：项目最大贡献是什么？

我把仿真、RL、MPC、TCP bridge、handoff gate、接受门控和日志诊断接成闭环，并能通过 16 次训练排错和 872 步失败窗口分析定位系统级问题。这比单独展示一个训练结果更贴近系统测试和工程验证岗位。

Q12：600 steps 和 1200 steps 怎么区分？

600 steps 是短时域验证窗口，用来比较 PPO、baseline 和 defaults；1200 steps 是压力测试窗口，用来暴露长时域失败机制。两个口径必须分开讲。
